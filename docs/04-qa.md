# QA and critique

The site was built first, then critiqued in a real browser, fixed, and re-tested.

## Method

- **Harness.** `scripts/capture.mjs` takes scroll-sampled screenshots at 1440×900, 1280×720, 834×1112 and 390×844. It also runs a reverse-scroll pass and a keyboard pass, collects console errors, and checks for horizontal overflow. Every run was repeated with `reducedMotion: 'reduce'`.
- **Six independent critics, each with a different lens, tested the production build.** The lenses were:
  - art direction;
  - motion;
  - responsive art direction;
  - accessibility (WCAG 2.2 AA, with axe-core);
  - content honesty, from the point of view of Sapience AI's head of marketing communications;
  - front-end engineering.
- **Adversarial verification.** A separate skeptic re-ran each lens's findings in the browser and tried to refute them.
- **Result:** 64 findings confirmed and 0 refuted. Every confirmed finding was addressed, and the fixes were re-checked with the harness plus scripted behaviour tests (`scripts/dev/`).

## Round 3 — the brand-aligned redesign

The palette became cream, near-black, white and one purple, with Libre Baskerville and Inter, near-black Chapters VI–VII and square security tiles, plus quieter supporting motion. It was also rebuilt to be served from `mousabatarseh.com/sapienceai`.

Four critics reviewed the production build on a local Apache set up like the real host (a WordPress root, a neighbouring app folder, and the site in `/sapienceai/`). Each had a different lens:
- brand alignment, compared against sapienceai.co;
- motion and accessibility;
- responsive behaviour and regressions;
- sub-path deployment and disclosure.

A verifier for each lens tried to refute every finding. **Result:** 32 confirmed and 2 refuted, and all 32 were addressed. Where a verifier found the proposed fix incomplete, its better fix was used.

## Known limits (what still needs real-world testing)

- Only Chromium was available in this environment. Safari (including iOS Safari's collapsing toolbar) and Firefox still need testing on real devices.
- Hairline legibility and the 2px presenter-mode ink need checking on the Seattle review projector.
- Core Web Vitals should be measured on real mid-range hardware. The headline waits up to 1.8s for its font before it is set (FE-7).
- The opening take is long (520vh). Customer testing should say whether it holds attention or needs shortening, and the scroll ranges are one table in `src/motion/record.ts`.
- Scenario copy and the flagged claims (see `/notes`, Open questions) need Sapience AI's confirmation before any real use.
