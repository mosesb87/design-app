HighMerchandising · /collections/belts

HighCatalog data · tags

The tags contradict the products.

Filters, the Google feed, search and email segments all read these tags. A karat filter that returns silver belts loses trust, and conflicting karat data is a product-claims risk on a luxury site.

Fix

Move product facts into metafields with one allowed value each: metal (Silver / 24K gold-plated / Mixed), leather, width, collection family. Tags stay for merchandising only. HighCatalog data · SEO · accessibility

Every image of a product says the same thing.

products.json · Hollyhock Black Silver product page HTMLcatalog alt text filled in: 0 of 722 images the theme falls back to the product title, so on the Hollyhock Black Silver page all 18 images read: alt="Hollyhock Black Silver" (front, side, buckle detail and on-model shots are indistinguishable)

Screen-reader shoppers hear the same name eighteen times. Google Images, a real discovery channel for visual luxury goods, gets one repeated phrase. Feeds read the empty field, and missing or identical alt text often appears in ADA demand letters.

Fix

Fill alt text from a template in one bulk pass: “Hollyhock belt in black calfskin with silver five-ring hardware, front view”, then “…, worn at the waist”, and so on. Add it to the launch checklist so new products ship with it.

DEH-101 · Merchandising · from flag 01

Sold-out products drop to the end of collection grids, and their tiles offer the waitlist

Priority HighEffort 1–2 daysSpec & QA eCommBuild Developer

Context

Collection order is set by hand, so sold-out products stay where they were placed. On September 16, slot 10 of All Belts was a belt sold out in all five sizes, while the $250 best sellers sat at slots 33 and 34.

/collections/belts · desktop 1440px · Sept 16Slot 10 → SOLD OUT Hollyhock Crystal Black Silver · $495 · 0 of 5 sizes
Slot 33 → Constance Black Silver · $250 · Best Seller badge
Slot 34 → Constance Black Gold · $250 · Best Seller badge

Build

  1. Products with no available size move after every in-stock product, in every collection grid. The hand-set order of in-stock products doesn't change.
  2. A sold-out tile shows “Join the waitlist” and opens the back-in-stock form for that product. No price-only dead end.
  3. When any size comes back, the product returns to its hand-set position.

Approach

Sort where the grid is built. If Algolia renders collection pages, rank on an in-stock attribute there. If Shopify does, use a sold-out-last app or a small job that calls the Admin API's collectionReorderProducts when inventory changes. Don't sort in Liquid per page, because that breaks across pages.

Done when

  • Given a product with zero available sizes, when any collection page loads, then it appears after all products with at least one size available.
  • Given an in-stock product in slot 5, when another product sells out, then its order relative to the other in-stock products is unchanged.
  • Given a sold-out product restocks one size, when the next inventory sync runs, then it's back in its hand-set slot within 15 minutes.
  • Given a sold-out tile, then it shows “Join the waitlist” and no add-to-cart, on mobile and desktop, with filters applied.

QA

  • On a duplicate theme, set a test product's stock to 0 and check All Belts, Best Sellers and New Arrivals.
  • Restock one size and confirm it moves back.
  • Run Lighthouse on All Belts before and after to confirm the page isn't slower.

Measure & rollback

  • Collection click-through, add-to-cart rate from collections, waitlist sign-ups, compared over two weeks before and after.
  • Rollback: switch the app off or republish the previous theme.
  • Out of scope: pinning best sellers by price tier. That's a merchandising task, done by hand.
DEH-102 · Analytics · from flag 12

One GA4 tag, one Tag Manager container

Priority HighEffort half a daySpec & QA eCommBuild Developer + Marketing

Context

Two Tag Manager containers load on every page, and the GA4 property loads twice. Page views and events can be counted twice, which makes every weekly number less reliable. It also adds main-thread time on phones.

page source · Lighthouse 12 mobile (lab) · Sept 16GTM-KSX9D6X · GTM-P8P6WVRR → two containers
G-Q891RMV74D → loaded twice
Google Tag Manager main-thread time ≈ 2.9 s · Yandex Metrica present

Build

  1. Audit both containers with marketing. List every tag, its owner and whether it's still used.
  2. Move the tags that are still needed into one container and remove the other snippet from the theme.
  3. Confirm the purchase event fires once through Shopify's customer events.
  4. Remove pixels no one owns, such as Yandex Metrica, after marketing confirms.

Done when

  • Given the homepage, a collection, a product page and checkout, when Tag Assistant runs, then it shows one GA4 configuration for G-Q891RMV74D.
  • Given a test order, when it completes, then GA4 DebugView shows exactly one purchase event.
  • Given any page load, then DebugView shows one page_view.

Measure & note

GA4 sessions and page views will drop when duplicates stop. I'd mark the change date in the weekly note so no one reads it as a real decline, and compare conversion with Shopify's own numbers for two weeks.
