Sec. 01 Findings · for the Web Development & Technical SEO Lead role

The page that sells SEO has no structured data.

Bran Marketing is the outsourced marketing department for industrial manufacturers, manufacturers' reps and wholesaler-distributors, and it is hiring a Web Development & Technical SEO Lead to build the web side of that department. On getbran.com, /web-design-seo carries no JSON-LD, and only 5 of 22 sitemap pages carry any. All 6 team pages still hold Wix placeholder copy, and Marsh & Moore, the build Bran presents as a case study, has 0 of 36 pages with a meta description. None of that is a backlog problem, so the department should start with a build standard, not a backlog: what I'd fix in week one, a line card you can filter, and the 90-day standard I'd run.

Ships on

The same standard on WordPress or Wix

Same fields, same facet names, same JSON-LD shape on either platform. That shared shape is the build standard.

WordPress

Custom post type + taxonomies

  • Content model a product post type; taxonomies for manufacturer, category, size range, material and lead time; specs as post meta; the spec sheet as an attachment on the product.
  • Facets FacetWP or a custom WP_Query with tax_query behind this same checkbox UI, filter state in the query string so a filtered view is shareable.
  • URLs /line-card/{category}/{product}/ via rewrite rules; manufacturer and category archives become landing pages.
  • Schema one wp_head hook builds Product, DigitalDocument, Offer and BreadcrumbList from post meta, so no editor touches code.
  • Performance server-rendered list, page cache, lazy images; only the facet script ships.

Wix

CMS collection + dataset filters

  • Content model a Products collection with reference fields to Manufacturers and Categories, tags for size range and material, a Document field for the PDF.
  • Facets a dynamic list page with dataset filters, or Velo wixData.query().hasSome() behind this checkbox UI; Wix Search for the text box.
  • URLs dynamic item pages at /line-card/{slug}; category pages from the Categories collection, picked up by the sitemap automatically.
  • Schema structured-data variables in the dynamic page's SEO settings, or wixSeo.setStructuredData() in Velo for the Product + DigitalDocument graph.
  • Performance the platform already ships 61 to 63 script tags per page at the median across the three Wix sites sampled, so keep sections and apps per page lean.

Sec. 03 Plan

Ninety days: a standard first, then the first build under it.

The findings above are not a backlog to grind through. They are what a build standard prevents: template leftovers, pages without schema, line cards that can't be filtered. So the department starts by writing the standard, uses the own-house fixes as its first test, then ships one client build the same way.

  1. Days 1–30

    Audit and baseline

    • Access: Search Console, GA4, Wix and WordPress admin, DNS. One URL inventory from robots.txt and every sitemap, this page's method made repeatable.
    • Baseline by page type: schema coverage, title and description lengths, H1 count, HTML weight, script count, TTFB; Lighthouse and CrUX when quota allows.
    • Own-house fixes: team slugs and placeholder copy, one canonical URL for the triple post, Service + BreadcrumbList on all 22 sitemap pages, noindex on /groups, /forum and /members, one H1 per post.
    • Deliverable: a one-page before/after in the same numbers as this review.

  2. Days 31–60

    Build standard

    • Templates for line card, manufacturer page and product/spec-sheet page on WordPress and Wix, with this prototype's facet UI.
    • Schema library: Organization, Service, BreadcrumbList, Product, DigitalDocument, Offer, BlogPosting, Person, validated in QA.
    • Migration checklist: URL inventory, redirect map, 404 sweep, alt text, metadata, sitemap and robots, launch QA.
    • Performance budget per template and a launch checklist: viewport, canonical, one H1, description, schema, alt coverage.
    • Estimating and time-tracking template so web work fits inside client credits and account leads see where hours go.

  3. Days 61–90

    First build under the standard

    • One client build or migration end to end: scope, estimate, build, QA, launch, redirects verified in Search Console.
    • Process documented where the team works: templates, checklists, handoff notes, a written definition of done.
    • Handoff: designers and account managers can brief web work without a developer in the room.
    • Retro against the posting's criteria, with numbers; the standard revised from what the build taught.
